**Method.** Colour tables are generated by script from the CSS, not hand-copied. Component tokens come from parsing every class string in each component file:

- **semantic token**: a class whose colour value is a `bg-`/`txt-`/`otl-`/`fr-` token, e.g. `text-txt-primary`.
- **primitive**: a class that uses a raw palette step, e.g. `bg-primary-600` or `text-white`.
- **dead class**: a class the MYDS preset doesn't generate.

The colour guideline (`color.mdx`) is **image-only**. Its token tables are PNGs served from the docs site and aren't in the repo, so it can't be diffed textually. For colour, code is the only machine-readable source.

## 1. Colour

### How the layers work (code)

- **Primitive colours** are space-separated RGB triplets on `*` in `color.css`, named `--_{family}-{step}`. The families are `white`, `black`, `gray` (with extra steps 850 and 930), `primary`, `danger`, `success`, and `warning`.
- **Semantic tokens** are defined in `light.css` on `:root` and remapped in `dark.css` on `.dark`. Each is `var(--_primitive)`, optionally followed by `/ <alpha>`.
- **Tailwind exposure.** The preset's `theme.extend.colors` exposes each semantic token as `"<token>": "rgb(var(--<token>))"`, so a token is usable with **any** colour utility: `bg-bg-white`, `text-txt-primary`, `border-otl-gray-200`, `ring-fr-primary`. It also works on off-label utilities like `bg-txt-danger` and `bg-otl-divider`, which components actually use. Alpha tokens work because `rgb(R G B / 0.4)` is valid CSS.
- **Primitives in Tailwind.** The preset also exposes primitives under `gray`, `primary`, `danger`, `success`, and `warning` (with `<alpha-value>` support), plus `white` (`DEFAULT`, `disabled` = white @ 40%). `theme.colors` is **replaced**, not extended, so Tailwind's default palette (blue, red, etc.) is unavailable.
- **Theme switching** is **only** the `.dark` class swapping CSS variables. No component uses a `dark:` variant, and the preset sets no `darkMode`. Anything styled with a primitive stays the same colour in both themes.
- **Resolved values.** Every hex below is resolved by script. Alpha is shown as a percentage and as 8-digit hex.

### Colour observations (⚠ = anomaly worth a decision)

1. ⚠ **`otl-warning-300` points to the danger scale.** It resolves to `danger-300` (light) and `danger-700` (dark), while `otl-warning-200` uses `warning-*`. This looks like a copy-paste bug. The same pattern holds in both themes.
2. **Steps 500 are theme-invariant.** `bg-{black,primary,danger,success,warning}-500` resolve to the same primitive in both themes, because 500 is the pivot of the inversion. Every other `bg-{family}-N` step inverts: light N maps to primitive N, and dark N maps to primitive 1000−N (50↔950).
3. **`bg-black-*` is a foreground-ish ramp that inverts.** `bg-black-900` is `gray-900` in light and `white` in dark. `bg-black-950` → `white` and `bg-black-50` → `gray-950` in dark.
4. **`txt-white` flips to `gray-900` in dark.** It means "text on a filled or inverted surface", not literal white.
5. **Some state tokens are identical to their base in light.** `bg-washed-active` equals `bg-washed` (both `gray-100`), and `bg-dialog-active` equals `bg-dialog` (both `white`). They only differ in dark.
6. **Disabled tokens are inconsistent in form.**
   - `bg-{primary,danger,success,warning}-disabled` are **opaque** (step 200 in light, step 950 in dark).
   - `bg-white-disabled`, `bg-black-disabled`, `txt-*-disabled`, and `otl-*-disabled` use **40% alpha**.
   - `txt-danger-disabled` is based on `danger-600` in light, but `txt-danger` is `danger-700`. Every other `txt-X-disabled` uses the same step as `txt-X`.
7. **Not exposed.** `bg-black-600` and `bg-black-950` are defined in both themes but missing from the preset's colour map, so no Tailwind class exists for them.
8. **Status outline tokens were commented out.** Five `otl-*-{600|700}-20` tokens are commented out in both theme files. `tag.tsx` uses the equivalent primitives with alpha instead (`border-primary-600/20` and so on), so tag borders **don't re-theme** (see §3).
9. **Token count.** 100 live semantic tokens: 69 `bg-`, 14 `txt-`, 15 `otl-`, 2 `fr-`. The "~130" in the map was an estimate.
10. **The palettes are Tailwind-derived with custom steps.**
    - `gray` is Tailwind *zinc*, except `gray-500` (`#6B6B74`, where zinc-500 is `#71717A`) and the added 850 and 930.
    - `primary` is Tailwind *blue*, except steps 200–500.
    - `danger`, `success`, and `warning` are Tailwind *red*, *green*, and *yellow*, except `success-300`.
11. **Docs-site-only palette.** `packages/style/index.js` also exports `preset_fumadocs`, an HSL mapping for the docs site's chrome. The map rules the docs chrome out of scope, so it's noted here only.

### Spacing

- Code **extends** Tailwind's default 4px-based scale with three values: `2.5` = 10px, `4.5` = 18px, and `10.5` = 42px.
- The guideline lists 4, 8, 12, 16, 20, 24, 32, 40, 48, and 64px, all already in Tailwind defaults. Its "where to use" column says:
  - 8px: gap in button groups, and between fields and labels.
  - 24px: gap between sub-sections and cards.
  - 32px: gap between main sections.
- ⚠ The guideline doesn't mention 10px, 18px, or 42px. 18px (`4.5`) is the mobile edge gutter that the grid page *does* describe.
- Components also use many arbitrary pixel paddings (`px-[10px]`, `py-[6px]`, …), mainly in pill, date-field, and search-bar.
